# Yuki 3.7.1 发布说明

Yuki 3.7.1 是 3.7.0 之后的烧钱扫描热修：把水位尺子、观察抽取、视觉缓存、自主门槛和
Rollup 模型白名单对齐到实际会花钱的路径。没有新 Alembic。Plugin API 仍为 `2.0`。
Genie-TTS Worker 内部版本保持 `1.9.0`。

从 3.6.1 升级仍走 [3.7.0 升级指南](../upgrade-3.7.0.md)。本版只重建 Bot，不改 schema。

## 行为变化

- Rollup 水位、未覆盖计数和热尾切分改用 Prompt `main_agent_history` 尺子，与前台渲染同源。
  压缩模型输入仍走 `rollup_source_projection`。换尺后应对未覆盖字符做 recount，避免库存仍是旧投影。
- 256 条热尾 floor 优先于 20480 字符 target。短消息可以让 Prompt 超过 target；最终前台检查仍用 admit，不是死循环。
- 群观察轮次（Bot 不回复）不再入队 Memory V2。被 @ 或会回复的轮次仍抽取。ledger / profile / observe 仍写。
- 当轮 Vision 成功后，对单图再写一条 `meme` 缓存别名，表情分类可复用，不再对同一张用户图打第二路。
- `CONVERSATION_AUTONOMOUS_ADMISSION_THRESHOLD` 默认改为 `80`。生产若仍写 `0`，几乎每条群消息都会开主 Agent。
- `CONVERSATION_ROLLUP_LLM_ORIGINS` 真正生效：batch 内全部 origin 都在白名单才打压缩模型；空或混合 batch 整批 extractive。
  自主出站打标 `autonomous_group`；插件后台保持 `plugin_background`；人类入站（含 observe）仍是 `user_message`。

## 不会改变什么

- Alembic head 仍为 `0042`。没有新迁移。
- Plugin API 仍为 `2.0`。
- 不改 Prompt 语义，不压 256 条热尾，不把字符 target 改成 fail-closed。
- 不合并 Vision 与 Emoji 两路 prompt。`vision_grid` 仍是显式选表情的第三条路。
- 不发明 `group_observation` origin。

## 升级要点

1. 将 `YUKI_VERSION` 改为 `3.7.1`。
2. 确认 `CONVERSATION_AUTONOMOUS_ADMISSION_THRESHOLD=80`（或你要的运营值）。不要留生产 `0` 除非故意让群里几乎每条都插话。
3. 只重建一个 Bot 实例。NapCat 不要动。
4. 验证 `/healthz` 返回 `version=3.7.1`。

回退时停止 3.7.1，启动上一版 3.7.0 镜像即可；schema 兼容。
