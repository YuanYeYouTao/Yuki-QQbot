# Yuki 3.6.0 发布与升级说明

Yuki 3.6.0 删除强制 Planner，由 Conversation / Memory / Capability Runtime 在模型前完成本地
准备，再进入 Main Agent。这是破坏性升级：Alembic head 为 `0040`，Plugin API 为 `2.0`，
Genie-TTS Worker 内部版本保持 `1.9.0`。

从 3.5.3 升级的锁定顺序、配置映射和回退规则见
[3.6.0 升级指南](../upgrade-3.6.0.md)。架构见
[3.6.0 运行时](../architecture/yuki-3.6.0-runtime.md)。本地性能数字见
[3.6.0 Runtime 性能报告](../performance/3.6.0-runtime-report.md)；端到端回放门槛尚未认证。

## 行为变化

- 普通聊天不再经过 Planner。私聊、@、回复机器人直接进入 Main Agent，不再产生 necessity 分数。
- 群聊自主参与只做本地评分；默认 `read_only`，`memory_change` 只接受用户消息来源。
- Plugin background 不再经 Planner SILENT，改为 tool-free 生成。
- emoji-only 必须走 Main Agent `send_emoji`，不再由 Planner 预置表情跳过 Agent。
- `model_profiles.toml` 必须是 schema v3。未迁移的 v1/v2 启动 fail-fast，并指出
  `qq-ai-bot-cli setup migrate-3-6`。
- 声明 Plugin API `1.0` / `1.1` 或仍使用 `planner.signal.register` 的插件会被拒绝或撤销批准。
- Tool Scope 改为 Semantic Namespace；Capability Search 只做本地 FTS5 BM25。
- Flash Tool Selection 与 `ModelTask.TOOL_SELECTION` 已删除，不映射旧
  `MCP_TOOL_SELECTION_MODE`。
- Memory 是独立 Runtime Session：被动预取由会话合同决定，显式读写走 Main Agent 工具。

## 安全与性能

Memory / Tool 安全回归由现有单元测试、破坏性升级回归和 Memory Release Check 覆盖：自主群默认
`read_only`，`memory_change` 只接受用户消息来源，Plugin background 为 tool-free。没有 600 轮
脱敏回放，因此不填写成对安全通过率。

本地结构性能见 [3.6.0 Runtime 性能报告](../performance/3.6.0-runtime-report.md)。端到端
P50 −35% / P95 −20% 按 07-PLAN §6.1 **尚未认证**，本版本不外推该数字。

## 首次安装

仅需 Docker Engine / Docker Desktop 与 Docker Compose v2。正式支持 `linux/amd64`。

1. 从 GitHub Release 下载 `install.sh`（Linux）或 `install.ps1`（Windows）。
2. Linux 执行 `chmod +x install.sh && ./install.sh`；Windows PowerShell 执行
   `powershell -ExecutionPolicy Bypass -File .\install.ps1`。
3. 安装器下载精确的 `3.6.0` 部署包并用 `SHA256SUMS` 校验，然后拉取 Bot 镜像。
4. 按向导填写管理员 QQ、主模型配置，并选择需要的扩展能力。
5. 安装器完成 Compose 启动和健康检查后，打开 <http://127.0.0.1:6099> 登录 NapCat。

默认安装目录是当前目录下的 `yuki/`。Linux 可传 `--dir PATH`，PowerShell 可传
`-InstallDir PATH`。机器人 QQ 号由 NapCat 实际登录账号决定。

## 从 3.5.3 升级

不要把新部署包直接解压覆盖现有目录。安装器在识别到已有部署后会：

1. 拉取精确的 3.6.0 Bot 镜像，此时不启动服务。
2. 停止旧 Bot，确认数据库写进程已退出。
3. 快照 `.env`、配置、`.mcp.json` 以及数据库/WAL/SHM。
4. 校验 checksum 与 `PRAGMA integrity_check`。任一步失败都不会启动 `migrate-3-6`。
5. 运行 `qq-ai-bot-cli setup migrate-3-6`，再打开 Guided Setup。
6. `docker compose config` 通过后启动 3.6.0。新镜像执行 Alembic `0037`–`0040`。

回退只能恢复同一套升级前快照并启动 3.5.3。不要对已执行 `0040` 的库做 Alembic downgrade。

## 健康检查

`/healthz` 应返回 `status=ok`、`version=3.6.0` 和 `database=ok`。不再包含
`planner_configured` / `planner_active_requests`。
