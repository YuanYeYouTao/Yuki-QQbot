# Yuki 3.6.1 发布与升级说明

Yuki 3.6.1 为长会话补上 Conversation History Rollup：有覆盖摘要之后主动缩短原文近窗，用
SESSION 前沿换回被切掉的连续性。这不是第四套 Memory。`chat_events` 仍是唯一原文；摘要不写入
`memory_facts`，不参与 Activation / Recall Receipt / Memory Mutation。

Alembic head 为 `0041`。Plugin API 仍为 `2.0`。Genie-TTS Worker 内部版本保持 `1.9.0`。

从 3.6.0 升级的顺序、配置和回退见 [3.6.1 升级指南](../upgrade-3.6.1.md)。合同见
[会话历史 Rollup](../architecture/conversation-rollup.md)。本地测量见
[3.6.1 History Rollup 性能报告](../performance/3.6.1-history-rollup-report.md)。没有生产
Provider 账单，不填写未测的 `prompt_tokens - cached_tokens`。

## 行为变化

- 默认启用 Rollup。水位即将丢掉前缀时，同步写入 extractive 摘要（零 LLM），立刻可进 Prompt；
  后台 Flash 再把同一 `source_fingerprint` 升级为结构化摘要。没有 extractive / active 覆盖时，
  禁止把原文切掉。
- Prompt 顺序为 STATIC system → SESSION system → 未覆盖近窗原文 → 当前消息 + TURN。
  SESSION 先占历史字符余额，再选近窗。rollup 不进第一条 static system，也不挂在当前消息前缀。
- 近窗缩短后，Main Agent 可用 `get_chat_history_around` 按 `#event_id` 回读被覆盖原文。
  现有关键词搜索仍在。
- Flash 默认只压缩 `TurnOrigin.user_message`。群自主与插件事件默认只走 extractive。
- Worker 不可用时普通聊天继续；已有 Summary 的会话重启后仍按落库 `coverage_end` 编译近窗。
- L0 成员按 `event_id` 排序落库。`occurred_at` 与插入顺序不一致时不再让聊天轮失败；覆盖写入
  失败时本轮退回原文近窗，并记 `conversation_history_coverage_skipped`。
- Context Reset 开启新的摘要 epoch。旧 epoch 摘要不得进入新窗口。
- 运维：`qq-ai-bot-cli history-rollup status|inspect|rebuild|invalidate|reconcile`。
  inspect 输出默认脱敏，不含 `rendered_text` 与事件正文。Rebuild 默认 dry-run，需 `--commit`。

## 不会改变什么

- 不删除、不改写 `chat_events`。
- Memory V2 事实、证据、Dream、Activation 路径不变。
- 普通聊天前台不增加 Compaction 模型调用。extractive 同步写入必须保留。
- 点餐 / artifact / 当轮工具 JSON 账单不在本版本承诺范围内。
- Plugin API 仍为 `2.0`。3.6.0 的 Planner 删除合同不变。

## 首次安装

仅需 Docker Engine / Docker Desktop 与 Docker Compose v2。正式支持 `linux/amd64`。

1. 从 GitHub Release 下载 `install.sh`（Linux）或 `install.ps1`（Windows）。
2. Linux 执行 `chmod +x install.sh && ./install.sh`；Windows PowerShell 执行
   `powershell -ExecutionPolicy Bypass -File .\install.ps1`。
3. 安装器下载精确的 `3.6.1` 部署包并用 `SHA256SUMS` 校验，然后拉取 Bot 镜像。
4. 按向导填写管理员 QQ、主模型配置，并选择需要的扩展能力。若开启 Flash，向导会为
   `conversation_compaction` 写入 flash 路由。
5. 安装器完成 Compose 启动和健康检查后，打开 <http://127.0.0.1:6099> 登录 NapCat。

默认安装目录是当前目录下的 `yuki/`。Linux 可传 `--dir PATH`，PowerShell 可传
`-InstallDir PATH`。机器人 QQ 号由 NapCat 实际登录账号决定。

## 从 3.6.0 升级

不要把新部署包直接解压覆盖现有目录。现有 3.6.0 部署：

1. 快照 `.env`、`config/`、`.mcp.json` 以及 `data` 下数据库/WAL/SHM。
2. 将 `.env` 中的 `YUKI_VERSION` 改为 `3.6.1`。
3. `docker compose pull` 后 `docker compose up -d`。新镜像执行 Alembic `0041`。
4. 若 `config/model_profiles.toml` 还没有 `conversation_compaction` 路由，运行时会从已有
   Flash 任务补一条；也可显式写成 `conversation_compaction = "flash"`。

回退：停止 3.6.1，恢复同一套升级前快照，将 `YUKI_VERSION` 指回 3.6.0。`0041` downgrade 只删除
rollup 表，不恢复已生成的摘要；生产回退以快照为准。

从 3.5.3 直接升级到 3.6.1 时，先完成 [3.6.0 升级指南](../upgrade-3.6.0.md) 中的
`setup migrate-3-6` 与备份门，再按上表启动 3.6.1 镜像。新镜像会连续执行 `0037`–`0041`。

## 健康检查

`/healthz` 应返回 `status=ok`、`version=3.6.1` 和 `database=ok`。Alembic version 为 `0041`。

关闭 Rollup Worker 或设置 `CONVERSATION_HISTORY_ROLLUP_ENABLED=false` 时，普通聊天仍应可用；
后者回到原文高低水位窗口。
