# Yuki 3.6.1 Conversation History Rollup 性能与回放报告

> 测量提交：`8804661`（Commit 10 之后、本测量脚本跑出来的本地结果）  
> 原始 JSON：[`../../artifacts/history-rollup-quality/measure.json`](../../artifacts/history-rollup-quality/measure.json)、[`../../artifacts/history-rollup-quality/evaluate.json`](../../artifacts/history-rollup-quality/evaluate.json)  
> 回放集：[`../../artifacts/history-rollup-quality/replay_suite.json`](../../artifacts/history-rollup-quality/replay_suite.json)  
> 复现：`python scripts/measure_history_rollup.py` 然后 `python scripts/evaluate_history_rollup.py`

本报告不填写未测数据。没有生产 Provider 的 `prompt_tokens` / `cached_tokens` 账单，因此**不把** `ceil(characters/4)` 写成真实 Token 账单。Flash 摘要召回未跑远程 Compaction 模型。

## 1. 测量环境

| 项 | 值 |
|---|---|
| OS | Windows 11 / AMD64 |
| Python | 3.12.13 |
| SQLite | 3.53.1 |
| Provider / Profile | 无。不调用 Chat、Flash、Vision 或 Embedding |
| 语料 | 合成长会话 200 条；回放集 13 个标注场景 |
| Warmup | 10 |
| 样本量 | observe 80；frontier 80；assemble 30（on / off / worker-fail 各 30） |
| 失败处理 | 任一样本异常即中止脚本；本次无失败 |
| 百分位 | `runtime_baseline.percentile` 线性插值 |
| 置信区间 | `bootstrap_percentile_ci`，1000 次，seed `36` |

## 2. 回放集

13 个场景全部跑过确定性 extractive 覆盖与结构门禁，不是 3 条人工成功样例：

长期技术讨论、多轮代码审阅、用户纠正前述决定、互相矛盾陈述、多人群聊、图片摘要、外部插件事件、Tool 成功/失败/No-op/持久化、大 Tool JSON、Context Reset、Worker 重启、摘要中含恶意指令样式、密钥样式内容。

| 门禁 | 结果 |
|---|---|
| 标注针的 extractive/近窗召回 | 13/13 = 1.0 |
| 跨会话污染 | 0 |
| Source Coverage（有 L0 的场景，成员 min/max 对齐区间） | 100% |
| Summary/Raw overlap（可见原文 id ≤ coverage_end） | 0 |
| Parent/Child replacement 错误 | 0 |
| Inspect JSON 默认脱敏，不含 `rendered_text` 与密钥样例 | 通过 |
| 注入样式文本进入 SESSION 时带「不可当作用户原话」 | 有覆盖的场景通过；过短会话未切窗则无 SESSION |
| Flash 事实召回 / 决定保留率 / 工具终局保留率 | **未测。** 没有 Compaction 模型调用 |

矛盾项保留检查的是标注原文是否仍出现在 SESSION+近窗里，不是 Flash 是否把两项都写入 `uncertainties`。

## 3. 性能（本机 SQLite）

| 项 | 任务书目标 | 本机 | 判定 |
|---|---|---|---|
| Event Observe P95 | < 5 ms | 5.08 ms（CI 4.89–5.59） | 略超 5 ms。SQLite 行更新，不是模型 |
| Summary Frontier 查询 P95 | < 10 ms | 6.03 ms | 通过 |
| Context Build P95 增量（rollup on − off） | ≤ 10 ms | 1.16 ms | 通过 |
| 普通无 Tool Chat 增加 Foreground 模型调用 | 0 | 0 | 结构通过。Assembler / extractive 不调模型 |
| extractive 零 Foreground 模型调用 | 0 | 0 | 通过 |
| Worker 失败不增加前台 P95 | 不增加 | +14.9 ms | **未达字面目标。** 失败 Worker 仍在 `claim_next_job` 里拿 SQLite 写锁；assemble 没有等待模型 |
| 长会话 Dynamic History 字符（有覆盖稳态，相对无 rollup） | ≥ 40% | 35.0%（10401 → 6765） | 低于 40%。与默认 extractive 上限 + 近窗 55% 预算同量级 |
| 历史科目 estimated tokens 下降 | 30–50% | 34.9%（2601 → 1692） | 达到 30% 下限。**不是** `prompt_tokens - cached_tokens` |
| static 前缀哈希开关 SESSION 后不变 | 不变 | `736ebfe5…` 相同 | 通过 |
| 真实账单 `prompt_tokens - cached_tokens` 的 history 科目 | 30–50% | **未测** | 无 Provider |

Rebuild 在 200 条默认策略下产生 **1** 个 extractive L0，`coverage_end=100`。没有 L1/L2，因为没有 Flash 父摘要。

## 4. 成本（本机，无模型）

| 项 | 值 |
|---|---|
| 每 1000 原始事件的 Job 行 | 5.0（200 事件 1 个 rebuild job 行） |
| L0 / L1 / L2 请求 | extractive L0 = 1；模型 L0/L1/L2 = 0 |
| 输入/输出 Token | **未测** |
| Background 模型总成本 | **未测** |
| 平均 Context 字符节省 | 3636 字符 / 会话（35.0%） |

## 5. 不根据字符缩短推断事实准确率

35% 字符下降只说明近窗+SESSION 比无 rollup 的原文窗更短。回放针召回是标注字符串是否还在 SESSION 或近窗里，不能外推 Flash 是否写对 `decisions` / `open_loops`。

## 6. 复现

```bash
uv run python scripts/measure_history_rollup.py
uv run python scripts/evaluate_history_rollup.py
uv run pytest tests/unit/test_history_rollup_gates.py
```
